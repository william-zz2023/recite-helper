# 背诵助手

原生 HTML、CSS、JavaScript 的静态网站，继续支持 GitHub Pages。包含音乐背诵和政治手册纯文本复习。政治资料来自用户提供的两册扫描 PDF，经本机 OCR 生成；原 PDF 不随网站发布。网站不引入第三方运行依赖、打包器或数据库。

## 本地预览

在项目目录运行：

```sh
npm start
```

然后访问 http://127.0.0.1:8000/ 。该命令使用 Python 3 自带的静态服务器；也可以直接运行 `python3 -m http.server 8000 --bind 127.0.0.1`。不需要执行 `npm install`。

页面通过 JavaScript 模块加载 JSON 题库，需要使用 HTTP 预览地址。直接双击 `index.html` 的 `file://` 方式不再是受支持的预览方式。

只有 `main.js` 负责组合全部页面。功能页面通过 `navigation.js` 按名称切换，不直接互相调用入口；服务层不导入页面。语音控制器和打卡存储通过参数接收运行环境、时钟或存储，测试不再从 HTML 截取脚本。

原有练习页面状态由 `state.js` 管理。读后复习通过独立的 `reading-review.js` 服务持久保存进度；政治页面使用独立的资料与进度服务。音乐题库和计分规则保持原样。

## 修改入口

- 修改资料标题、徽标或题库路径：`src/app/config.js`。
- 修改音乐题目、答案、关键词或挖空版本：`data/music/questions.json`。现有题目 ID 是打卡关联依据，不要随意重新编号。
- 修改界面：对应的 `src/features/` 文件和 `src/styles/app.css`。
- 修改语音兼容逻辑：`src/services/speech.js`；界面提示在 `src/features/listening.js`。
- 修改打卡数据规则：`src/services/study-history.js`；日历展示在 `src/features/history.js`。

## 数据兼容

音乐打卡继续使用 `recite-helper.music-overview.study.v1`，备份继续使用原来的 `version: 1` 结构。上线到同一网站地址后，原浏览器的打卡记录可以继续读取，无需迁移或清空数据。旧 JSON 备份仍可以合并导入。

浏览器按来源保存网站数据。本地文件、`http://127.0.0.1:8000` 和 GitHub Pages 的记录相互独立；如需迁移，请在原页面导出，再在目标地址导入。无账号和跨设备自动同步。

存储失败时仍保留当前页面记录并提示导出；无法解析的旧存储仍保留，不会被新记录覆盖。

## 音乐读后复习（2026-10-21 新增）

在音乐首页选择“阅读模式”，每读完一题点击“读完本题，加入复习”。清单按题目编号去重，翻页不自动加入。当天阅读打卡只记一次，但完成复习后可以再次将同一题加入新一轮；清单支持移出尚未开始复习的题目。

底部点击“复习这 N 题”开始。读满 5 题有提示，1 题也能开始。复习开始后题目范围固定，暂存期间新增的题目留到下一轮。提供三种方式：

- 口头背诵＋自评：先只看题目，可展开关键词，再查看答案，选择“记住了 / 还不熟 / 没背出”。不录音、不自动打分，自评和是否用过提示单独写入打卡。
- 关键词提示＋输入作答：显示已有关键词，输入完整答案后复用原有文字核对规则。
- 全文默写：只显示题目，输入后核对文字。相似度达到 80 分记为通过，分数仅作内容核对参考。

小结支持仅重背本轮待巩固题，或继续阅读。暂存返回保留当前阅读位置，完成后通常接着读下一题；已经到最后一题时留在原题。首页有继续未完成复习的入口。手机收起目录，正文 16px、题目 18px，操作按钮至少 44px 高。

`#music-reading` 和 `#music-review` 用于刷新恢复页面。清单、草稿、已展开答案和复习进度保存在 `recite-helper.music-overview.reading-review.v1`。打卡的原键不变，增加 `recall` 活动类型；不将口头自评计入练习通过次数。每次结果有固定事件编号，刷新或跨午夜恢复不会重复打卡。

音乐打卡页的备份新增可选 `readingReview` 字段，包含清单、阅读位置和本轮草稿；旧版仅打卡备份仍能导入。导入保留当前未完成轮次、合并待复习与待巩固清单；导入较早备份可能恢复之前已经移出的清单题目。记录保存在当前浏览器，不自动跨设备同步。

实现与校验说明见 `docs/music-reading-review.md`。更新前的 GitHub 旧版代码与完整 Git 历史已备份到本机 `tmp/backups/`，备份不随网站发布。

政治页的 TXT 下载还需要一起发布 `output/text/`。不要把 `tmp/`、原 PDF 或 OCR 编译产生的本机可执行文件上传到仓库。

## 政治复习

首页顶部选择“政治复习”，或访问 `http://127.0.0.1:8000/#politics`。支持：

- 上下册切换、分部／专题／题目三级目录；手机使用原生模态目录抽屉，正文按专题连续阅读，方向键切换专题。
- 搜索本册知识点，结果直接定位对应题目。句子不再按扫描行或 PDF 页码切断。
- 手机默认正文 16px、题目 20px、正文行高 1.75；长题干使用 17px。字号可增大至 24px。
- 续读位置和书签可定位到题目；逐题遮住答案，手机底栏显示当前题目并提供遮答及打卡操作。
- 点击“本题已背”才会记录当天题目；同页不同题分别记录，跨页的同一道题只记录一次。浏览、滚动和收藏不会自动打卡。
- “原文出处”显示原始逐页 OCR 文字与 PDF／印刷页码，正文不再出现页码导航。跨页表格在可确认结构时合并，复杂图表保留校对提示。
- 按日期查看复习内容，单独导出和合并导入政治备份。

政治数据键为 `recite-helper.politics.reading.v1`，与旧音乐打卡分开保存。沿用 version 1，新增可选 `unitId` 区分题目，`page` 继续保留作来源定位。旧页记录和页书签保留为旧版记录，不会被转换成“本页所有题都已背”。导入备份合并书签、日期与题目，续读位置取较新记录；合并书签采用并集，导入旧备份可能恢复之前删除的书签。`readerFontSize` 独立保存新版字号，缺省为 16，避免沿用旧阅读页的 18px 默认值。没有账号和跨设备自动同步。

政治文本覆盖上册 238 页、下册 168 页，含原稿封面与附页。原书页码来自每页边缘的印刷数字，没有采用固定偏移；未识别到的页码留空。上册第五部分在 PDF 第 201 页开始，对应原书第 195 页。

这些是未逐字校对的 OCR 文本。正文中的字词、公式、表格、框架图和多列文字可能识别错误，因此政治页面不提供基于 OCR 的自动判分。详见 `output/text/解析说明.md`。

如需从原 PDF 重做文字识别，macOS 上可编译 `scripts/ocr-politics.m`（使用本机 Apple Vision、PDFKit），按页保存到 `tmp/pdfs/politics-ocr/upper/` 和 `lower/`，然后依次运行 `python3 scripts/build-politics-text.py`、`python3 scripts/build-politics-reader.py`。前者检查全部页码，保留逐页来源；后者根据位置、题号与专题标题整理阅读结构，保留来源页和结构整理审计。日常使用网站不需要 OCR 工具。原识别 JSON、TXT 没有因阅读版整理被覆盖。

## 已知的原有问题

以下问题在拆分前已经存在，本次保留题库和既有练习逻辑，没有将它们混入结构重构：

- 原题库有 19 个挖空版本出现占位编号超出答案数组的情况，包括第一个题目的 30% 和 50% 版本，进入这些填空题时会报错。需要单独校对题库后修复，不能据现有答案数组猜测替换。
- 练习目录跨批次跳转混用了整轮索引和批内索引，跳到第 11 题及以后可能出错。普通的按顺序分批练习不经过此跳转路径。

浏览器验证中的填空练习使用了原题库里编号有效的题目；自动测试通过不代表上述旧问题已经解决。
